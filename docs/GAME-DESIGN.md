# 게임 디자인 문서

`Tales of Cultivation` 의 전체 게임 흐름과 시스템 정의. 전투 세부 규칙은 `BATTLE.md` 참조.

---

## 1. 핵심 루프

```
[맵]
  ├─ 수련 (Cultivation)
  ├─ 성장 (Growth)        ──▶ [전투 (Battle)] ──▶ 결과 반영 ──▶ [맵] 으로 복귀
  ├─ 이벤트 (Event)
  └─ 대사 (Dialogue / 비주얼 노벨)
        ⋮
[엔딩]
```

- 플레이어는 **맵** 화면에서 다음 행동을 선택한다. 선택지의 종류는 노드(또는 위치) 별로 다르다.
- 한 노드에서 발생할 수 있는 기본 활동:
  - **수련**: 시간을 들여 스탯 / 경지 진척도를 올린다. 자원을 소비할 수 있다.
  - **성장**: 카드 / 장비 / 보유물품을 정비. 시장·대장간·약방·도장 등 시설 노드에서.
  - **이벤트**: 임의의 단발 분기. 선택지에 따라 보상·페널티·플래그가 결정된다.
  - **대사 (비주얼 노벨)**: `DialoguePart` 가 처리하는 정적 컷씬. 종료 시 다음 단계로 자동 이행. `speaker` 가 비어 있는 행은 나레이션으로 간주되어 화자 이름 박스가 출력되지 않음.
- 일정 조건 (스토리 플래그 / 경지 / 보스 토벌 등) 을 만족하면 **전투** 가 트리거된다.
- 전투 결과는 맵 상태에 반영 (체력·자원·플래그 갱신, 보상 카드/장비 획득, 노드 해금/봉쇄 등).
- 메인 스토리 분기·엔딩 플래그가 모두 충족되면 **엔딩** 으로 진행.

### 게임 시작 → 종료 큰 흐름

1. 인트로 비주얼 노벨 (입문 시험 등 시작 컷씬).
2. 첫 전투 (튜토리얼 성격 / 검종 장로 시험 등).
3. 맵 진입. 이후 맵 ↔ 활동 ↔ 전투 반복.
4. 메인 분기 / 사이드 분기 진행도에 따라 한 가지 엔딩으로 수렴.

## 2. 경지 (Realm) 와 카드 착용 제한

- 경지는 5단으로만 정의된다 (`realmtable.json`, `rank` 1~5):
  1. **범인** — 수선의 길에 들지 못한 평범한 인간.
  2. **연기** — 기운을 단련하여 영기를 받아들이는 단계.
  3. **결단** — 영기를 단전에 응결시켜 단을 형성한 단계.
  4. **원영** — 원영을 형성하여 의지를 영체로 분리할 수 있는 단계.
  5. **화신** — 신의 모습으로 화하여 천지의 권능을 다루는 단계.
- 각 경지 안에 세부 단계 (1단/2단 등) 는 두지 않는다. 경지 자체가 큰 도약이며, 누적 진척도로 자동 승급하지 않는다.
- 캐릭터는 charactertable 의 `realmId` 로 시작 경지를 지정.
- 카드는 자체 **요구 경지** 를 가진다 (`cardtable.json` 의 `grade` 또는 신규 `requiredRealmId` 필드로 표현 가능).
- **돌파 규칙**:
  - 플레이어의 현재 경지 < 카드의 요구 경지 → 그 카드는 덱에 착용할 수 없다 (편성 화면에서 잠금 표시).
  - 경지 돌파(승급) 가 일어난 직후, 신규로 해금된 카드를 덱에 추가 가능.
  - 이미 덱에 있는 카드는 경지가 떨어지더라도 자동 제거되지 않는다 (현재 디자인 가정 — 추후 변경 가능).
- 경지 돌파 자체는 **이벤트로만** 발생. 게이지 누적이나 자동 승급 없음. 각 경지마다 사전에 정의된 돌파 조건 (특정 보스 처치, 특정 보유물품 사용, 특정 NPC 인가, 특정 플래그 충족 등) 이 만족되면 해당 이벤트가 트리거되어 한 단계 승급한다.
- UI: 카드 아이콘 좌상단의 grade 색상 + 잠금 시 회색/자물쇠 오버레이로 표시. PlayerPart 의 "경지" 탭에서 현재 경지 / 다음 경지 / 돌파 조건 힌트만 표시 (진척도 게이지 없음).

### 데이터 변경 가이드 (미구현 / 도입 시 권장)

```json
// cardtable.json 의 카드 항목에 추가
{
  "id": 12000010,
  "displayName": "고수의 풍모",
  "requiredRealmId": 10000003,
  ...
}
```

```js
// 덱 편성 검증 (의사 코드)
function canEquipCard(player, cardDefinition) {
    const requiredRealmRank = realmRank(cardDefinition.requiredRealmId);
    const playerRealmRank = realmRank(player.realmId);
    return playerRealmRank >= requiredRealmRank;
}
```

## 3. 강화 시스템

플레이어는 전투 외 활동을 통해 다양한 축으로 강화된다. 각 축은 별도의 인벤토리 / 슬롯 / UI 를 가진다.

### 3-1. 장비 (Equipment)

- **카테고리**: 무기 / 방어구 / 장신구 등 (슬롯형). 한 슬롯엔 1개만 장착.
- **획득**: 시장에서 구매, 던전/이벤트 보상, 보스 드랍.
- **제련 (Refinement)**: 대장간 노드에서 자원을 소비해 장비의 등급/스탯을 강화. 실패 확률 / 자원 소모 / 등급 상한 존재.
- **효과 적용 시점**: 전투 시작 시 장착 장비의 보너스가 PlayerState 의 base 스탯에 가산되어 반영. (예: 무기 → 시작 행동력 / 시작 카드 cost 감소 / 특정 카드 데미지 +N)

### 3-2. 특수 보유물품 (Unique Treasures)

- 1회 획득되는 고유 아이템. 보유 자체가 패시브 효과.
- 예시:
  - "검령패" — 산패에 검술 카드가 1장 추가된다.
  - "양기단지" — 매 턴 시작 시 행동력 +1.
  - "주작령" — 첫 턴에 드로우 +2.
- 일부 보유물품은 **이벤트로만** 획득 가능 → 플레이 분기를 만든다.

### 3-3. 소모품 (Consumables)

- 사용 시 소비되는 일회성 아이템.
- 맵에서 사용 (수련 보조, 체력 회복, 플래그 직접 변동) 또는 전투 중 사용 (1턴 공짜 회복 등) 모두 가능하도록 설계.
- 인벤토리는 수량 제한 / 무게 제한 둘 중 하나로 관리 (디자인 결정 필요).

### 3-4. 자원 종류

| 자원 | 용도 |
| --- | --- |
| 영석 (재화) | 시장 구매, 제련 비용 |
| 약초 / 광석 | 제련·연금 재료 |
| 영단 (소모품) | 경지 돌파 보조 / 체력·자원 회복 |
| 명성 / 평판 | 특정 NPC 호감도, 분기 조건 |

각 자원은 인벤토리에서 합산 표기되며, 강화/이벤트의 비용 / 보상 단위로 사용된다.

## 4. 스탯 / 플래그 기반 노드 해금·봉쇄

맵의 노드는 다음 조건에 따라 동적으로 노출/은폐/잠금/해제된다.

### 4-1. 조건 종류

| 조건 종류 | 예시 |
| --- | --- |
| 경지 | "축기 이상이면 진입 가능" |
| 스탯 | "근골 ≥ 10 이면 절벽 등반 노드 노출" |
| 보유물품 | "주작령을 가지고 있으면 남쪽 사당이 열림" |
| 스토리 플래그 | "검종 장로 격파 후 동굴 발견" |
| 진행 일자 | "30일 차 이후 시장에 새 상인 등장" |
| 호감도 / 평판 | "한무휘 호감도 50 이상이면 비밀 수련" |
| 환경 (계절·시간대) | "야간에만 묘지 노드 활성" |

### 4-2. 데이터 모델 (권장)

```json
// maptable.json (예시)
{
  "id": 20000010,
  "name": "검종 후산 동굴",
  "description": "사람 발길이 끊긴 곳.",
  "activities": ["수련", "이벤트"],
  "visibleConditions": [
    { "type": "flag", "key": "killed_elder", "equals": true },
    { "type": "stat", "key": "perception", "min": 8 }
  ],
  "lockedConditions": [
    { "type": "item", "key": "lantern", "missing": true }
  ]
}
```

- `visibleConditions` 가 모두 만족되면 맵에 표시.
- `lockedConditions` 중 하나라도 참이면 표시는 되지만 클릭 불가 (사유 툴팁 노출).
- 노드 자체가 영구 봉쇄되어야 하는 분기는 별도 `permanentlyClosedFlag` 로 관리.

### 4-3. 이벤트 / 전투의 플래그 변경

- 이벤트 종료 시 `setFlag("killed_elder", true)` / `addItem("주작령")` / `addStat("perception", +1)` 같은 후처리.
- 한 이벤트가 여러 노드의 가시성을 동시에 바꿀 수 있다 → 맵 갱신은 매 화면 진입 시 전수 재평가.

## 5. 화면 / 파트 구성

| 파트 | 역할 |
| --- | --- |
| `MapPart` (구현 — 골격) | 맵 노드 표시, 활동 선택, 노드 가시성/잠금 평가. 노드별 활동 (이동·수련·성장·이벤트·대사·전투) 클릭 시 외부 콜백으로 위임 |
| `PlayerPart` (구현 — 골격) | 탭형 정보창 (경지/능력 · 인벤토리 · 산패 · 어빌리티 · 관계 · 저널) |
| `DialoguePart` (구현 완료, 구 NovelPart) | 대사 컷씬. `speaker` 가 빈 문자열이면 나레이션으로 간주하여 화자 이름 박스를 출력하지 않음 |
| `BattlePart` (구현 완료) | 전투 (`BATTLE.md` 참조) |
| `DungeonPart` (구현 — 골격) | **서브 사이클**. 던전 정의 (방 그래프 + 보상) 진입 후 룸 진행. 출구 도달 = 완료(보상 지급), 탈출/패배 = 보상 없음. 룸 종류별 내부 파트 트리거는 `onRoomEntered` 콜백으로 외부 매니저에 위임 |
| `CultivationPart` (신설 예정) | 수련 미니게임 / 진척도 누적 / 경지 돌파 트리거 |
| `GrowthPart` (신설 예정) | 시장·대장간·덱 편성 등 성장 메뉴 |
| `EventPart` (신설 예정) | 단발 분기 이벤트 (선택지 + 결과) |
| `EndingPart` (신설 예정) | 엔딩 분기 결과 + 크레딧 |

각 파트 간 전환은 메인 매니저 (`main.js`) 가 담당. 전환 시 PlayerProfile (스탯 / 인벤토리 / 플래그 / 덱) 만 영속되고, 파트 내부 상태는 매번 reset.

### 5-1. 핫키 (개발 중)

`main.js` 의 강제 전환 핫키 — 1: 대사, 2: 전투, 3: 머지, 4: 맵, 5: 플레이어 정보, 6: 던전.

### 5-2. 메인 사이클 vs 서브 사이클

- **메인 사이클**: `MapPart` → 활동 (`CultivationPart`/`GrowthPart`/`EventPart`/`DialoguePart`) → `BattlePart` → `MapPart`.
- **서브 사이클 (`DungeonPart`)**: 메인 사이클에서 던전 진입 노드를 선택하면 진입. 던전 안에서는 `DungeonPart` 가 자체 룸 그래프를 진행하며, 룸의 종류에 따라 `BattlePart` / `DialoguePart` / `EventPart` 를 일시적으로 호출하고 종료 후 다시 `DungeonPart` 로 복귀. **완료 시에만** 던전 정의의 보상이 PlayerProfile 에 합산되며, 탈출(자발) 또는 패배는 빈 손으로 메인 사이클의 맵으로 복귀.
- 메인 사이클 화면(맵/플레이어 정보) 은 던전 안에서는 진입하지 않는다 — 던전 진행 중엔 던전 컨텍스트만 유효.

## 6. 영속 데이터 (PlayerProfile)

전투/이벤트/맵 사이를 가로지르는 **단일 진실원본**. 저장/로드의 단위.

```text
PlayerProfile
├─ characterId / nickname
├─ realmId                 (현재 경지)
├─ stats                   (근골, 영근, 인지, 명성 ...)
├─ ownedCards              (보유 카드 인벤토리)
├─ equippedDeck            (덱 편성 — 요구 경지 충족 카드만)
├─ equipment               (슬롯별 장비)
├─ uniqueTreasures         (특수 보유물품)
├─ consumables             (소모품 인벤토리)
├─ resources               (영석 / 약초 / 광석 / 영단 ...)
├─ flags                   (스토리 / 이벤트 플래그)
├─ relationships           (NPC 호감도 / 평판)
├─ mapState                (현재 노드, 방문 이력, 영구 봉쇄 노드 목록)
└─ daysPassed              (진행 일자)
```

저장은 단일 JSON 직렬화 + LocalStorage / 파일 (플랫폼별).

## 7. 엔딩 분기

- 게임 종료 트리거: 메인 스토리 클리어, 사망, 특정 플래그 만족 (배신 / 은퇴 / 등선 등).
- 엔딩은 다음 축들의 조합으로 분기:
  - **경지 도달 단계** (도사 / 진인 / 선인 ...)
  - **소속** (검종 잔류 / 탈종 / 적대 종파 합류)
  - **주요 NPC 관계** (호감도 / 적대도)
  - **특수 보유물품 보유 여부**
  - **결정 플래그** (특정 이벤트의 핵심 선택)
- 단순 분기 대신 **점수 + 가중치** 로 엔딩을 결정하는 방식 추천 (가능한 엔딩 N 개를 후보로 두고 가장 높은 점수의 엔딩을 출력).

## 9. 진행 우선순위 (제안)

1. PlayerProfile 자료구조 + 저장/로드.
2. MapPart 의 골격 + 노드 가시성/잠금 평가기.
3. CultivationPart, GrowthPart, EventPart 골격.
4. 경지 돌파 + 카드 착용 제한 룰 (cardtable 의 `requiredRealmId` 기반).
5. 장비 / 보유물품 / 소모품 인벤토리 + 시장·대장간 노드.
